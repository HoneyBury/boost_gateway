# ADR: v3.6.3+ Linux x64-only patch releases

- Decision ID: `v363-linux-x64-release`
- Status: `accepted`
- Date: 2026-08-01

## Context

Production runs on the always-on Linux x64 `miniserver`; the Linux x64 `aoi` host is the
build and test runner. ARM runner work is temporarily paused. The v3.6.2 release remains an
immutable, historically supported three-platform release, but requiring unavailable ARM hosts
would prevent the backend lifecycle fix from reaching production.

## Decision

- The v3.6.3 candidate and successor patch manifests contain only `linux-x64` runtime, debug symbols, SDK wheel and
  NuGet native payloads, with their SPDX SBOMs, provenance and aggregate checksums.
- Tag builds and post-release verification run only on the admitted native Linux x64 runner.
- SDK package content changes use version `4.2.1`; v3.6.2 SDK 4.2.0 assets are never replaced.
- Linux ARM64 and macOS ARM64 v3.6.2 assets remain available as historical immutable releases.
  They are not rebuilt, deleted, or represented as current patch assets.
- Candidate workflows may retain ARM platform capabilities, but they do not expand the patch
  release manifest. Adding a release platform requires a later reviewed manifest change.

## Validation And Rollback

- The release job fails unless exactly one Linux x64 runtime, symbol archive, wheel and NuGet
  package, four matching SBOMs and two SDK provenance documents are present.
- Published-asset verification downloads from an empty directory and verifies the immutable
  tag/SHA, checksums, symbol pairing, SDK RID, clean consumer and attestations.
- Production upgrades only through `manage_release_deployment.py`; rollback retains the verified
  v3.6.2 deployment and persistent Redis volume. Canary clocks restart after the successor
  deployment record is installed atomically.
